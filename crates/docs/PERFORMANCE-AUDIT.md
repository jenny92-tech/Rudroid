# 性能机制与当前决策

本文保留截至 2026-10-19 的有效结论和必要负面结果；逐轮流水账已删除。
当前五标题功能交付见[验收](ACCEPTANCE.md)，参数及 ABI 门控以[运行策略](RUNTIME-POLICY.md)为准。

已完成多条公共路径的等价工作量精简，也验证了有代价的可选策略。
**尚无五标题公平 C/Rust 对照证明整体更快、更省内存或“已经最优”。**
证据分别来自 RK3566/Mali-G52、约 4 GiB，以及 A523/Mali-G57、约 1 GiB；
不能推广到 R36S 或所有低性能设备。

## TrimUI 可选 Vulkan 对照（2026-10-19）

`rust-kit-4fb32b16c8f74a8c`，丝之歌 Tut_01 同一存档副本、固定位置，输出
1280×720、渲染 640×360、原有 45 上限与 balanced 内存档不变。两后端相同画质，
关闭 GLES 专有绘制裁剪；加载完成且 PCM 正常后，各取 2×25 秒窗口。
当前 CPU 上限分别为 1128/1200 MHz，ondemand；未调频、未改系统驱动。

|---|---|---|
| 成功呈现调用/s | 21.26 / 21.26 | 20.66 / 20.62 |
| 整套 CPU，100% 为一核 | 114.6–114.8% | 104.2–104.3% |
| 玩家 RSS | 684–685 MiB | 682–684 MiB |

Vulkan 本轮 CPU 约低 9%，呈现吞吐约低 3%，换页空间约多 76 MiB，
**未见帧率净收益，继续默认 GLES**。CPU、内存和流畅度分别判断，不能沿用
MiniLoong 的收益。这里是固定场景短窗，不代替战斗、长时间或其他标题验证。

固件未启用 FTRACE；只读采样已有成功呈现计数器，确认 render 前模拟 vsync 关闭，
不把 nativeRender 循环数当 FPS。计数器间隔 20ms，不据此声称精确帧时间分位数。
CPU/PSS/SwapPss 包含玩家及私有会话进程；不以玩家 PSS 降低冒充整机省内存，
也不把 swap 的逻辑字节直接当作 zram 物理占用。原始记录在忽略目录
`crates/target/trimui-wayland-20261019/`。

早期 Vulkan 运行在加载期间因音频队列 1 秒超时而终止混音，未采信为公平对照。
现在超时返回零接收、队列不增长，FMOD 继续处理原生工作并可在后续块恢复；
错误和关闭仍失败。7 种真实 JNI 退出/拒收场景、64 项 SDL 单测及新真机 PCM/退出验证通过。

## 当前机制与默认行为

| 机制 | 当前处理 | 成本、收益与边界 |
|---|---|---|
| JNI 临时引用与对象图 | native 调用自动 local frame，返回引用提升；叶子直接释放、无递归剥离链、残留环按需追踪 | 不靠定时全 VM 扫描回收；引用与并发最后删除必须保住 owner。安全性和资源归还不能因性能绕过。 |
| 字符串与字段查询 | 字符串编码随 owner 释放；固定 GL 字符串一次初始化；字段直接声明索引 | 热点避免重复复制、锁和继承临时分配；不建立全局字符串内容缓存。现场对照没有证明每个标题都会提帧。 |
| 内部缩放呈现 | 保留原尺寸、滤波和状态语义，省略已满足的 GL 状态设置与无关 getter 工作 | 已做实际入口正向验证、像素/状态回归和调用计数；没有跳过游戏绘制，不改变分辨率。 |
| ELF 文件映射与冷代码 | exec 介质文件映射、未修改代码按需驻留；noexec 保留校验后的复制回退并一次释放冗余源页驻留 | 重定位、复制、共享页与补丁保留必要缓存维护。没有游戏过程的定时回收；冷页 refault 与 PSS 变化需分别解释。 |
| 资源流缓冲 | 默认 balanced：每流 8 KiB / VM 总载荷 1 MiB；只为不可变包内小块读取按需申请 | close/最后引用释放归还预算；大块读取、存档和可变文件保持直接读取。不能解决引擎百 MiB 级堆占用。 |
| 音频 | 固定缓冲与回调周期背压；callback 不分配、加锁或做 I/O；完整清理时 stop/join 后释放 | 解决过度唤醒与所有权；更小队列、替换环形方案未获足够整游净收益，不用局部复制耗时代替整个输出成本。 |
| 帧节奏 | 两 profile 默认 target_fps=90、render_sleep_us=0，按本轮已耗时间只补剩余等待 | 不额外固定睡 16ms；成功 render/swap 返回不等于独立显示帧。 |
| Unity 额外回收 | 沿用引擎 GC；可选 memory_policy 未加入默认五标题，额外 GC/UnusedAssets 默认 false | 低内存通知也可能执行昂贵游戏回调。批量 AssetBundle 卸载默认关闭，不为少量内存增加重载或卡顿。 |
| 日志与诊断 | 普通报告有界；帧直方图、CPU 快照、追踪及内存采样显式开启 | 配对、实际入口和丢事件验证通过才采信；测帧率时关闭高扰动诊断。 |

实现所有权及前提见相应 [crate 导航](../AGENTS.md)；机制正确与整游净收益分别验收。

- 游戏插件识别并停用不需要的特效 renderer/pass，核对场景与完整 ABI，只在场景变化时处理。

  匿名形式可能每个 batch 都复制。合并/移除需确认输入和绘制顺序，不能全局跳过 framebuffer copy。
- 透明装饰、雾、粒子按标题精简，复用已有受限静态 Sprite/Behaviour 工具；碰撞、角色、HUD 与遮罩另行核对，
  不为剔除新增永久逐帧遍历或反复资源卸载。

Framebuffer 提示已在旧丝之歌 kit 做过开关实验：移动提交约 30.35 vs 30.20/s、GPU 均 800MHz，
温度不同、各一轮，没有稳定收益，不能重新包装成未测的新优化。中间附件/存储带宽仍可按具体 pass 审查；
已有 wayland_native 也不能在用户选择 sharp 时静默替换。上述路径主要作用于 GPU/内存带宽，
不要求视频编解码 VPU 参与，也不把节省的 GPU 工作转成软件逐像素处理。

## 编译与诊断实验

ThinLTO、PGO 和 `/proc/cpuinfo` 进程快照都已探索，并非“尚未开始”。
本机短程回切没有获得稳定净收益，普通 Release 与 cpuinfo_snapshot=false 仍是默认。
其他 CPU/标题可能不同，需要重新实测，不能把本机无收益解释成所有设备都无收益。
PGO 训练版不可交付；反馈输入、codegen 和同 kit 规则见[构建流程](../../BUILD-DOCKER.md#可选-pgo-训练与反馈编译)。

`unity_memory_policy` 的 diagnostic_only 为有界只读诊断，不减少内存。
历史人工高阈值压力实验不是真实 OOM，也没有证明 1 GiB 预算可玩；额外同步 GC
曾花费约 34–70ms、托管 used 少约 6MiB 而 heap/PSS 未降，不能据此开启默认回收。

## 现场数据能说明什么

- VS 内部呈现一次调用计数从约 75→40/提交；vs44/vs45 成功提交 49.70/50.95 次/s、
  p99 34.45/33.37ms、CPU 184.93/185.64%、PSS 944.08/943.54 MiB。
  基线 GPU 在 200/800MHz 变化，候选为 800MHz，温度亦不同、单轮样本；
  这些数字不能证明等价精简带来稳定全局 FPS 收益。
- VS 一次 CPU 采样约 Unity 46.21%、IL2CPP 20.86%、Mali 用户态 22.72%、libc 5%、
  JNI 2.16%、SDL 0.49%、Bionic 0.24%。这是 CPU 样本归属，不是 GPU 利用率，
  也不表示这些时间都能由兼容层消除。
- 已有正向控制、零丢事件的稳态 6 秒战斗窗口未观察到纹理分配/上传/删除；
  不能扩大为整个游戏没有资源重载或所有 I/O 路径无调用。
- 旧资料里“Rust 更快”的窗口有配置未读、混入加载/升级/死亡或 C 额外 sleep 等差异。
  保留原始结果解释原因，不将这些窗口列为公平端到端提速证明。

## 后续验收口径

1. 冻结同源码候选、资源/存档种子、设备/固件和完整 Unity build；同一配置只改目标变量。
   保持输出/渲染尺寸、画质、滤波与 FPS 目标一致，先复用已有采样，不无差别重跑全部游戏。
2. 截图和输入时间线确认相同页面与稳定/动态场景，剔除加载、过渡、升级和死亡。
   冷/暖缓存、进程年龄、温度与 DVFS 分别记录，必要时 A/B/A 回切。
3. 比较每帧 CPU、提交间隔 p95/p99/长帧、RSS/PSS/HWM、Swap/SwapPss、I/O/major faults
   与资源重载。PSS、托管 heap 与 GPU 页口径不同，不能直接相加或相减推算精确物理占用。
4. 追踪先验证实际入口，按字段精确核对 overrun、commit overrun、dropped events；
   缺字段或丢事件的数据拒绝采信。“零事件”不能自动证明没有调用。
5. 兼容修复与性能收益分开，省少量内存不能抵消卡顿。保留备份及失败数据，
   功能正确但净收益不明的机制保持可选；发布候选固定后再统一做受影响标题回归。

不同后端、Unity 版本和低端 CPU 的边界见[移植指南](HANDHELD-PORTING-WORKFLOW.md)。
继续优化优先针对实际热点与资源所有权，通用机制、库级插件和游戏配置分别归属，
不把单标题的偏移、回收阈值或调度策略写进通用默认。

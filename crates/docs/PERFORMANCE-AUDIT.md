# 性能机制与决策

本文说明采用条件、测量口径和必要负面结果。当前支持范围见 [验收](ACCEPTANCE.md)，
参数及 ABI 门控见 [运行策略](RUNTIME-POLICY.md)。现有证据来自 RK3566/Mali-G52
约 4 GiB 与 A523/Mali-G57 约 1 GiB 的指定标题和场景；没有五标题公平 C/Rust
对照证明整体更快、更省内存或已经达到最优，也不推广为所有低性能设备的结论。

## 测量口径

- 成功 render/swap/present 返回计数是提交吞吐，不是屏幕独立帧数。实屏、游戏运动、
  数字音频、保存和退出分别检查；黑屏期间的提交不能记作合格游戏性能。
- CPU 以一个逻辑核 100% 计。比较需固定画质、渲染尺寸、帧率目标、存档位置、缓存种子
  和运行库，记录实际频率、温度、线程及缺页；请求的固件性能档不等于实际频率。
- RSS、PSS、SwapPSS 和 GPU 驱动记账不能机械相加。SwapPSS 是逻辑换出量，
  不等于 zram 物理占用；Vulkan 对照应包含 Weston、seatd 等会话进程。
- 采样工具必须确认实际入口、时间窗与丢事件情况。截图和重诊断放在性能窗口外；
  工具退出码不代替玩家退出码。短窗、菜单和静止场景结果不能推广为完整玩法。

## 当前机制与默认行为

| 机制 | 当前处理与边界 |
|---|---|
| JNI 引用和对象图 | 调用内 local frame、返回引用提升、按需处理残留环；保留 owner 与并发最后删除契约，不做定时全 VM 扫描 |
| 字符串与字段 | 编码随 owner 释放，固定 GL 字符串一次初始化，字段直接索引；不建立全局字符串内容缓存 |
| 内部缩放呈现 | 保留尺寸、滤波及 GL 状态语义，省略冗余设置和无关 getter；不跳过游戏绘制 |
| ELF 映射 | 文件映射按需驻留；noexec 使用校验后的复制回退，必要补丁与缓存维护保留，无游戏期定时回收 |
| 资源流 | balanced 每流 8 KiB、VM 总载荷 1 MiB，按需申请并随 close/最后引用释放；存档、可变文件和大块读取直读 |
| 音频 | 固定缓冲和背压，callback 不分配、加锁或做 I/O；完整清理先 stop/join 再释放 |
| 帧节奏 | 两 profile 默认 target_fps=90、render_sleep_us=0，只补本帧剩余等待；不额外固定睡眠 |
| Unity 回收 | 沿用引擎 GC；额外 GC、UnusedAssets 和批量 AssetBundle 卸载不进入五标题默认 |
| 日志 | 普通运行仅有界异常上下文；追踪、帧直方图、CPU 和内存采样显式开启 |

机制正确与整游净收益分别验收。资源流的 0/1/16 MiB 预算不代表 Unity 总 RAM 上限，
也不是离线资源工具的 1/2/4 GiB 目标档；CPU 可读、字体及数据纹理等保护规则仍适用。
实现与所有权见 [workspace 导航](../AGENTS.md)。

## 显示与 Vulkan 边界

五标题默认 GLES、75% 渲染；丝之歌和吸血鬼在已登记机型、依赖及原生预检通过后
可手动选择 Vulkan。当前 Vulkan 仅覆盖已验 Wayland 路径、SDL 2.26+、单 guest
instance/device；预检不加载游戏，系统 ICD/GPU 驱动保持原样。

A523 丝之歌的私有 Weston 强制完整尺寸合成：75% 游戏缓冲 960×540，经合成器
输出 1280×720。缩小缓冲直接扫描曾出现满屏竖纹，人物输入仍响应且驱动错误计数
为零；强制合成的实屏回切已检查，因此不以成功 present 或零错误计数证明画面正常。
该策略仅作用于这一设备/标题，并同时用于能力预检与游戏。

完整高特效 Vulkan 读档黑屏仍未通过。旧局部黑块可能涉及呈现或捕获伪影，透明度、
fourcc 和同步候选未取得足以扩展验收的证据；不把候选解释写成已证实根因。
Weston 外部捕获曾断言，更早 RGA/内核异常仍无统一根因。CPU 缓冲可读、GPU 回读
或 DRM 元数据都不能替代物理面板确认；不以这些工具宣称所有视觉故障已解决。

### GLES 与 Vulkan 内存对照

A523 丝之歌，同场景副本、75% 渲染、50% 装饰物、balanced/45，新进程移动后静置，
5 次采样间隔 2 秒的中位数，单位 MiB：

| 路径 | 常驻 PSS | SwapPSS | PSS + SwapPSS | 系统 MemAvailable |
|---|---:|---:|---:|---:|
| GLES | 536.67 | 437.63 | 974.30 | 81.92 |
| Vulkan 全尺寸合成 | 475.78 | 519.31 | 995.09 | 83.88 |

Vulkan 包含其会话进程；常驻少约 60.89 MiB，换出多约 81.68 MiB，逻辑合计多约
20.79 MiB，不能称为整体节省 RAM。GPU 私有分配未单独计量，系统可用内存仅作背景。
该比较不是加载峰值、长期泄漏或帧率测试。1 GiB 下仍有换页、停顿及音频 underrun。

## 线程策略

可选渲染线程亲和性全局默认关闭，启动器只为 A523 丝之歌开启。它要求实际线程名、
主线程身份、原亲和性及一高容量核加两个等容量低核的在线拓扑符合；首次成功 GLES
或 Vulkan 呈现时由线程自身调整一次，不保存 TID、扫描线程、常驻轮询或修改频率。

低画质同进程回切中，GLES 为 36.84→20.15→36.68、Vulkan 为
39.60→20.35→39.80 次成功呈现/s，中间恢复原绑核；设置为 640×360、50% 装饰物
及低效果。这说明指定场景的 CPU 争用可改善，不代表正常画质或稳定 38 帧。
完整效果 1280×720 的 GLES 回切约 14.08→9.80→14.02，仍未达到稳定 30 帧。

FMOD 混音分配默认关闭，仅为 A523 丝之歌 Vulkan 开启。只调整 addon 自建混音线程，
原生 FMOD 流、Unity Job 和其他线程保持引擎管理；GLES 实验未见明确净收益。

Unity 启动前 single/multi 是独立策略，默认 `engine`，只对精确 Unity 6000.0.61f1
ARM64 身份开放。只有显式 `unity.render_thread_mode="memory_mode"` 才按内存档
映射，普通内存档不自动改线程模式。multi 可增加 CPU 和约几十 MiB PSS，不能用
无限制提交吞吐提高来证明相同输出目标下更省资源。契约见
[渲染线程模式](RUNTIME-POLICY.md#可选-unity-启动前渲染线程策略)。

## 有代价的可选策略

| 策略 | 当前决策 |
|---|---|
| Wayland 原生同尺寸缓冲 | 保留显式 wayland_native，默认 internal；局部收益不抵消滤波语义差异，不能静默跳过锐化 |
| noexec 介质的 exec 视图 | 仅已验标题/固件显式启用，复用文件 mapper；无资源复制、全局挂载更改或常驻监督器 |
| shader、texture、mip、音频预加载 | 按标题与消费者门控；上传 CPU、画质、驻留和重载代价分别验证 |
| Unity job workers | 局部降 CPU 伴随主线程成本和频率变化，未改通用默认 |
| 缩小引擎池 | 已观察实际采用值，但掌机未见驻留净收益，恢复原参数；虚拟容量减少不等于物理回收 |
| 额外 GC/批量卸载 | 未证明足以抵消游戏回调、重载和卡顿，默认关闭 |
| 强化缩放、framebuffer 提示、呈现半精度 | 候选没有取得通用整游净收益，部分标题有可复现回退，不进入默认 |

### 长音频加载

RK3566 / 4 GiB 的黑神话像素版固定场景中，保持音频载荷、采样率、纹理和布局，
仅调整长音频加载/预加载标志，压缩驻留与取消预加载组合约减少 46.5 MiB PSS。
提交率仍约 59.6/s，没有证明提帧、减少 CPU 或功耗；取消预加载还有过渡延迟风险，
压缩播放需要解码 CPU。正式资源保持原样，不自动修改公共资源工具或内存档默认。

尚未覆盖全部音频、GetData 等消费者、长时间缓存、1 GiB 硬件或其他标题。
不能把特定场景匿名内存变化当作整游内存上限。方法启发见
[d2r-mobile](../../docs/REFERENCES.md#d2r-mobile)。

## 离线纹理转换实测

离线工具按原始像素尝试 ASTC 档，生成完整 mip 后独立重读校验；保护字体、CPU 可读、
未知可读性、数据/HDR 和未知布局。目标档要求已验证的 GPU ASTC 支持，不能由 RAM
容量推定支持。文件载荷减少不能直接折算运行期 PSS、峰值、GPU 分配或帧率。

既有 BC/DXT 转换与更粗纹理档没有证明通用整游净收益，可能增加上传 CPU 或损失画质。
不同标题需检查流引用、mip、字体、GetData 等实际消费者以及画面；不自动改运行时 cap、
音频或游戏美术。可复用入口与范围见 [资源准备](../../tools/README.md)。

## 编译与诊断实验

ThinLTO/PGO 仅改变宿主 Rust 代码，不能重新优化闭源 Unity、IL2CPP 或 GPU 驱动。
现有有界对照未证明通用整游收益，普通 Release 默认保持原设置。代码体积减少不等于
同量物理内存节省；训练库、测试库及测量开关不得进入正式交付。

追踪和 CPU/GPU/内存采样会扰动被测对象。需核实实际函数入口、完整时间窗、丢事件、
场景运动及退出，不能把诊断值、工具超时、单张截图或空白输出当作性能结论。

## 音频与平台调参的证据边界

SDL requested == obtained 不证明设备没有格式转换；固定应用可见格式与设备原生
格式是两件事。桥接 f32 直通也不等于整个输出链无转换。
Docker/dummy 的单次缓冲或 ring 对照不能决定掌机默认缓冲、可听延迟或 FPS。
虚拟设备闭环和复制耗时只验证局部机制，真实 FMOD/硬件仍单独验收。

保留 [缓冲回归](../capability/linux/sdl_runtime/tests/audio_ab_buffer.rs)和
[虚拟设备闭环](../capability/linux/sdl_runtime/tests/audio_device_disk.rs)。
板级 DMC/DFI 依赖固件和内核；缺少测点保持 unknown，区分请求、驱动报告和实际效果。
通用音频修复不写系统频率或 governor，外部补丁边界见
[Aurknix](../../docs/REFERENCES.md#aurknix-音频与-dmc)。

## 后续验收口径

先验证真实入口、画面、输入、数字音频、保存和退出，再对相同构建/配置做多轮回切。
同时记录加载峰值、稳态、换出、会话进程与实际频率，并独立检查失败和异常路径。
没有公平重复对照的局部收益不升为默认，不将短程结果写成全关卡或长期稳定性保证。
